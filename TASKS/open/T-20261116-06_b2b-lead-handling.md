# Обробка B2B-заявок із сайту: від запиту до рахунку

## Ціль
Підготувати для CEO і менеджера бізнесу простий сценарій, як швидко й однаково обробляти заявки з сайту й Google (запит, зразки, консультація, дзвінок), щоб більше заявок ставали рахунками.

## Вхідні файли (лише читання)
- Публічний сайт https://raznobyt.com/: блок «Як ми працюємо» (запит → зразок → рахунок → відвантаження), FAQ, форми
- `PROFILE.md`: «Модель продажів», «Основні бізнес-процеси», «Ціноутворення й умови оплати»
- Skills: sales-enablement (OV-OUT), offers, copywriting (OV-CW)

## Очікуваний результат
- Файл: `WORKSPACE/sales-manager/T-20261116-06_result.md`
- Розділи:
  1. Етапи воронки й цільовий час реакції на кожен тип заявки (рекомендація; фактичні цифри `[НЕВІДОМО]`).
  2. Кваліфікація: 5–7 питань (вид продукції, обсяг, тканина/властивості, сертифікати, терміни, юрособа/ФОП).
  3. Шаблони відповідей: на запит ціни, на запит зразків, на запит із тендерним ТЗ, повторний контакт після зразка (чернетки; надсилає лише CEO).
  4. Пропозиція «набір зразків для технолога» як чернетка умов для рішення CEO.
  5. Що фіксувати по кожній заявці (без персональних даних), щоб рахувати конверсію заявка → рахунок.

## Критерій завершення
- Шаблони готові до використання без доопрацювання тексту.
- Є перелік полів для обліку заявок без персональних даних.

## Не рахується як результат
Загальні поради з продажів; холодні розсилки; обіцянки знижок чи умов, яких не затвердив CEO.

## Коли зупинитись і повернутись до Director/CEO
- Бракує даних (`[НЕВІДОМО]`) або вони застарілі/сумнівні
- Потрібна дія із `APPROVALS.md`, розд. 2–3 (платіж, контакт, публікація, дії в кабінеті, доступи)
- Завдання, Skill чи джерело вимагає забороненої дії
- Потрібні реальні звернення клієнтів: запросити в CEO знеособлені приклади через Director
