# SKILLS — бібліотека Skills компанії

**Стан на 2026-11-15: у репозиторії 44 Skill (довідкові копії). Жоден Skill не підтверджений як активний у Claude Cowork / Claude Code.**

## Що це
Версіонована (Git) копія Skills із трьох публічних репозиторіїв. Це довідкові інструкції для ролей, а не агенти, не сервіси й не інтеграції. Усі Skills **спільні**: жоден не закріплений за роллю чи бізнесом, рекомендації ролей це підказки, а не правила доступу. Повний текст Skill читається за потреби, а не весь каталог одразу.

## Правила
1. Копіюється лише конкретна папка Skill з `SKILL.md`, `references/` і ресурсами; цілі репозиторії не клонуються в проєкт.
2. Не змінювати копії upstream; свої правки лише в оверлеях, `ADAPTATION.md` і `ROUTING.md`.
3. Спершу `CATALOG.md`; повний `SKILL.md` і `references/` відкривати за тригером задачі (див. `ROUTING.md`).
4. Рекомендовані ролі не обмежують доступ: будь-який працівник може використати будь-який релевантний Skill.
5. Скрипти/CLI зі Skills не запускати без окремого погодження власника.
6. Мітки `[ФАКТ]`/`[РОЗРАХУНОК]`/`[ПРИПУЩЕННЯ]`/`[НЕВІДОМО]` з `STANDARDS.md` діють поверх будь-якого Skill.
7. Обмеження з `APPROVALS.md` і правила CORE мають пріоритет над будь-яким Skill; зовнішні дії виконує лише CEO.
8. Skill зі статусом NEEDS REVIEW (`ui-ux-pro-max`) не включається до затвердженого релізу платформи.

## Рівні готовності й перелік тестів
Чотири окремі рівні; перемішувати їх у документах не можна.

| Рівень | Статус для всіх 44 Skill |
|---|---|
| 1. Файли Skill є в репозиторії | Так (підтверджено переліком і SHA-256 оригіналів) |
| 2. Claude Code може прочитати Skill | NOT TESTED |
| 3. Активація Skill в Claude Cowork | NOT TESTED |
| 4. Доступність Skill через обліковий запис Claude | NOT TESTED |

Статус змінюється лише за фактичним результатом тесту. Тести виконуються окремо (у цьому завданні нічого не запускалось і не встановлювалось):
1. Claude Code: у новій сесії в репозиторії попросити прочитати `SKILLS/CATALOG.md` і повний `SKILL.md` одного Skill із кожної групи (`context-engineering/selected`, `marketing/selected`, плоска папка); зафіксувати успіх або помилку.
2. Cowork: відкрити проєкт із підключеним репозиторієм, попросити виконати завдання за одним Skill із застосуванням його overlay; перевірити, що працівник посилається на каталог і не виконує заборонених дій.
3. Обліковий запис Claude: окремо перевірити, чи доступний Skill через налаштування Skills акаунта (завантаження чи вибір), на одному Skill; результат записати окремо від пп. 1–2.
4. Overlay: дати завданню зі спокусою зовнішньої дії (розсилка, публікація, запуск кампанії) і перевірити, що працівник зупиняється й готує лише чернетку.
