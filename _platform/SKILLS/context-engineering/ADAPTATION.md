# Адаптація Context Engineering до COMPANY

Skills = довідкові принципи для Director, не фонові агенти.

1. **Оркестрація file-based.** Кожна роль окрема сесія; handoff лише файлами за `README.md` теки (один файл — один власник). `multi-agent-patterns` обирає схему, але не створює паралельних автономних агентів.
2. **Файли як пам'ять.** Джерело правди: `STATUS.md`, `TASKS/`, `WORKSPACE/<роль>/`. Чат-історія не є сховищем.
3. **Економія контексту.** Читати за потребою (JIT): заголовки, потрібні рядки. Повний `SKILL.md` і `references/` лише за тригером з `ROUTING.md`.
4. **Стискання.** Підсумок завдання ≤10 рядків; тижневий архів у `ARCHIVE/` лише від Director.
5. **Приймання (evaluation).** Результат приймається, якщо: є мітки фактів, джерела з датою, розділені факти/припущення, дотримано `APPROVALS.md`.
6. **Не застосовувати** механізми, що потребують власного runtime (KV-cache, фонові sandbox-агенти, цикли самозміни).
7. **Активація Skill у Cowork і Claude Code не тестувалась (`NOT TESTED`).** Доки це не підтверджено, застосовувати принципи через короткі правила й каталог `../CATALOG.md`, не називаючи це нативною активацією Skill.

## Доповнення за рішеннями CEO (2026-11-13)

8. **DATA/ і SOPS/.** `DATA/` лише для читання всіма AI-агентами, включно з Director (дані й реєстри записує лише CEO за пропозиціями Director); результати ролей лише у `WORKSPACE/<роль>/`. Операційні процедури: `../SOPS/`; при конфлікті SOP має пріоритет над Skill.
9. **long-horizon-prompting:** застосовувати лише критерій завершення, перелік результатів, що не рахуються, правила зупинки/повернення й чекліст приймання. Не застосовувати автономні мультиагентні запуски, портфелі паралельних підходів, «effort floors» і наполегливість без зупинки. Потреба зовнішньої дії або погодження завжди означає зупинку й запит до CEO.
10. У бібліотеці тепер є також `memory-systems`, `tool-design`, `context-fundamentals`, `context-degradation`, `advanced-evaluation`, `project-development` (плоскі папки в `../`); див. `../CATALOG.md`. Відсутні м'які залежності, яких досі немає (наприклад `harness-engineering`), необов'язкові й не блокують роботу. Скрипти цих Skills не запускати (OV-0); єдина реальна залежність, `numpy` у `memory-systems/scripts/memory_store.py`, не встановлюється.
11. **Доступ універсальний:** будь-який працівник може використовувати будь-який релевантний Skill; рекомендації ролей це підказки; повний текст читати за потреби. Правила виконання: overlays `../../LIBRARY/skills/OVERLAYS.md` (OV-0, OV-LH тощо) разом із CORE.
