# ТЗ для Store Builder: технічні SEO-виправлення raznobyt.com

## Контекст
Сайт: React-збірка з пререндереними HTML-сторінками (кожна сторінка це папка з `index.html`), сервер nginx/1.20.1 `[ФАКТ, заголовок Server, 2026-11-19]`. Код сайту, конфіг nginx і хостинг `[НЕВІДОМО]`, тому приклади нижче треба адаптувати до реального коду. Store Builder готує чернетки змін, CEO їх впроваджує.

## Що вже працює і не можна зламати
Після кожної правки перевірити, що збереглося (стан на 2026-11-19):
- canonical на всіх 666 URL: абсолютний, https, зі слешем, вказує на саму сторінку;
- hreflang `uk` / `ru` / `x-default` на всіх 666 URL, взаємний, у HTML і в `sitemap.xml`;
- `html lang` (`uk` / `ru`);
- у сирому HTML кожної картки товару є title, description, один H1, хлібні крихти й характеристики.

## Завдання 1. Редирект без кінцевого слеша через http (P1)
**Проблема `[ФАКТ]`:** усі 665 адрес без кінцевого слеша перенаправляються на `http://raznobyt.com/…/` і лише потім на https. Приклад: `https://raznobyt.com/catalog` → `Location: http://raznobyt.com/catalog/`.

**Зробити:**
1. У блок `server` для raznobyt.com у nginx додати:
   ```nginx
   absolute_redirect off;
   ```
   Якщо конфіг nginx недоступний, CEO звертається до хостингу: «редирект на кінцевий слеш має вести на https, а не на http».
2. У коді меню, шапки й футера дописати кінцевий слеш у 14 посиланнях:
   - UA: `/catalog/`, `/delivery/`, `/about-us/`, `/contacts/`, `/blog/`, `/news/`, `/documents/`;
   - RU: `/ru/catalog/`, `/ru/delivery/`, `/ru/about-us/`, `/ru/contacts/`, `/ru/blog/`, `/ru/news/`, `/ru/documents/`.
3. 301-редиректи зі старих адрес меню, які зараз віддають 404:
   ```nginx
   location ~ ^/catalog/personal/?$ { return 301 /catalog/sfera-poslug/; }
   location ~ ^/catalog/fire/?$     { return 301 /catalog/fire-safety/; }
   ```

**Критерії приймання:**
- `curl -sI https://raznobyt.com/catalog` → `301`, `Location: /catalog/` або `https://raznobyt.com/catalog/` (не `http://`);
- те саме для картки без слеша, наприклад `/catalog/workwear/tkan-workwear-tr-55`;
- у HTML будь-якої сторінки немає внутрішніх посилань без кінцевого слеша (крім файлів: `.xml`, `.pdf`, зображення);
- `/catalog/personal` → 301 на `/catalog/sfera-poslug/`; `/catalog/fire` → 301 на `/catalog/fire-safety/`.

## Завдання 2. Кешування HTML і sitemap (P1)
**Проблема `[ФАКТ]`:** HTML-сторінки й `sitemap.xml` віддаються з `Cache-Control: max-age=2592000` (30 днів). Відвідувач, який заходив раніше, до 30 днів бачить стару версію сторінок.

**Зробити** (приклад, адаптувати до чинного конфігу; найімовірніше, зараз там глобальне `expires 30d`):
```nginx
# HTML-сторінки і sitemap: браузер завжди перепитує сервер (ETag уже є)
location / {
    add_header Cache-Control "no-cache";
    # ...чинні try_files / index без змін
}
location = /sitemap.xml { add_header Cache-Control "no-cache"; }
location = /robots.txt  { add_header Cache-Control "no-cache"; }

# Файли збірки з хешем у назві: довгий кеш
location /assets/ { add_header Cache-Control "public, max-age=31536000, immutable"; }
```
Зображення в `/images/` з параметром `?v=` можна лишити з довгим кешем.

**Критерії приймання:**
- `curl -sI https://raznobyt.com/` і `…/catalog/workwear/` → `Cache-Control: no-cache` (без `max-age=2592000`);
- `curl -sI https://raznobyt.com/sitemap.xml` → `no-cache`;
- файл `/assets/js/index-*.js` → довгий кеш;
- після публікації нової версії сторінка в браузері, де сайт уже відкривали, оновлюється звичайним перезавантаженням (F5), без Ctrl+F5.

## Завдання 3. Title і description карток товарів (P1)
**Проблема `[ФАКТ]`:** title карток складається лише з артикулу («TR-35 TEFLON | Різнобит», медіана 17 символів) і однаковий для UA і RU. У 139 UA-карток description коротший за 70 символів.

**Шаблон title** (поля беруться з характеристик картки):
- UA: `Тканина {Артикул} — {Склад}, {Щільність} г/м² | Різнобит`
- RU: `Ткань {Артикул} — {Состав}, {Плотность} г/м² | Різнобит`
- Якщо довжина понад 70 символів, прибрати склад: `Тканина {Артикул}, {Щільність} г/м² — {Назва категорії} | Різнобит`.
- Приклад: «Тканина TR-35 TEFLON — 35% бавовна, 65% поліестр, 245 г/м² | Різнобит».

**Шаблон description** (лише для карток, де поточний description коротший за 70 символів; довші не чіпати):
- UA: `{Поточний опис}. Склад: {Склад}, щільність {Щільність} г/м², ширина {Ширина} см. Склад у Києві, від 1 м, зразки, доставка по Україні.`
- RU: `{Текущее описание}. Состав: {Состав}, плотность {Плотность} г/м², ширина {Ширина} см. Склад в Киеве, от 1 м, образцы, доставка по Украине.`
- Обрізати до 160 символів по межі слова. Тези «склад у Києві, від 1 м, зразки» взято з сайту; якщо CEO їх змінить, оновити шаблон.

**H1 не змінювати** (лишається артикул).

**Критерії приймання:**
- у сирому HTML і після JS title відповідає шаблону на всіх 622 картках;
- title UA і RU різні (слово «Тканина» / «Ткань» і мова складу);
- немає description, коротшого за 70 символів, і довшого за 160;
- canonical і hreflang не змінились.

## Завдання 4. Пагінація категорій (P1)
**Проблема `[ФАКТ]`:** у сирому HTML 14 категорій (UA і RU) немає жодного посилання на товари. Після JS видно 9 товарів і кнопку «Завантажити більше (N)». Пошукова система кнопку не натискає, тому більшість карток досяжна лише через sitemap.

**Зробити:**
1. Пререндерити сторінки категорій із першими N товарами як звичайними посиланнями `<a href="/catalog/<категорія>/<товар>/">` у HTML сервера (N = як зараз на сторінці, 9–24).
2. Сторінки пагінації: `/catalog/<категорія>/?page=2`, `?page=3`… (і RU-аналоги) з товарами в HTML сервера.
3. Під товарами блок посилань `<a href="?page=2">2</a> …`. Кнопку «Завантажити більше» можна лишити, але поруч мають бути звичайні посилання на сторінки.
4. На `?page=N` (N ≥ 2):
   - canonical на саму себе: `https://raznobyt.com/catalog/workwear/?page=2` (не на першу сторінку);
   - hreflang на відповідну сторінку іншої мови з тим самим `?page=N`;
   - title: `{title категорії} — сторінка N`; текстовий SEO-блок категорії показувати лише на першій сторінці.
5. `?page=1` → 301 на адресу без параметра. `?page=` більше за кількість сторінок → 404.
6. Сторінки `?page=N` у sitemap не додавати.

**Критерії приймання:**
- у сирому HTML `/catalog/workwear/` є посилання на перші N товарів і на `?page=2`;
- з першої сторінки категорії через посилання пагінації можна дійти до кожного товару цієї категорії (перевірка: сума товарів на сторінках = кількість товарів категорії);
- canonical і hreflang на `?page=2` вказують на `?page=2`.

## Завдання 5. Категорія `unknown` (P2, частина після рішення CEO)
**Проблема `[ФАКТ]`:** 10 URL `/catalog/unknown/…` (5 UA + 5 RU) у sitemap; сама категорія віддає 403; у хлібних крихтах цих карток порожня назва категорії («Каталог тканин › › Defender…»).

**Зробити зараз:** прибрати 10 URL `unknown` із `sitemap.xml`.
**Після рішення CEO** (куди віднести армійські тканини): перенести 5 товарів у реальну категорію, зробити 301 зі старих адрес на нові (UA і RU), виправити хлібні крихти.

**Критерії приймання:** у sitemap немає `/unknown/`; після переносу старі адреси → 301, хлібні крихти без порожньої ланки.
