# Результат: технічний і on-page SEO-аудит raznobyt.com

## Підсумок
1. **Чи може Google прочитати контент без JS?** Головна, каталог, 14 категорій і службові сторінки: **ТАК**. Картки товарів (311 із 333 URL у sitemap): **НІ**. Сервер віддає всім карткам той самий порожній шаблон: порожній `<title>`, без description, без H1, без характеристик. Навіть після виконання JS у картки порожній title, немає description і два H1.
2. Google бачить лише UA-версію. RU-версія перемикається кнопкою без окремого URL (зберігається в localStorage), тому для пошуку її немає.
3. Два пункти головного меню («Сфера послуг» → `/catalog/personal`, «Для пожежної служби та ДСНС» → `/catalog/fire`) віддають сервером **404**.
4. На всіх сторінках немає canonical, hreflang і структурованих даних. На категоріях без JS немає жодного посилання на товари, а з JS їх 9, решта сховані за кнопкою «Завантажити більше».
5. Головна проблема для комерційних запитів: картки товарів, тобто основний обсяг сайту, для Google порожні й однакові. Виправлення №1 у списку (розд. 5).

**Метод і джерело.** Усі перевірки 2026-11-16, 18:00–19:30 (Київ). Сирий HTML сервера отримано запитом GET без виконання JS (fetch у вбудованому браузері Claude). Це те, що Google отримує до рендерингу. Відрендерену сторінку перевірено тим самим браузером після виконання JS. Видачу Google, Search Console і PageSpeed Insights не перевіряв: доступу до них немає, а вебпошук у сесії працює не на Google.

## 3. Структура, перелінковка, розмітка

- **Категорії й ЧПУ** `[ФАКТ]`: латинські ЧПУ зі слешем, два рівні (`/catalog/<категорія>/<товар>/`), назва товару в URL дублює категорію (`tkan-workwear-…`). Проблеми: технічна категорія `/catalog/unknown/` (403) з 5 «army»-товарами в sitemap; одна тканина в кількох категоріях під різними URL. Рекомендація: один основний URL на тканину (або canonical на основну категорію), «unknown» прибрати з sitemap і перенести товари в реальну категорію. URL не змінювати без рішення CEO й плану 301-редиректів.
- **Змішана логіка категорій** `[ФАКТ]`: 5 категорій за застосуванням (робочий, медичний, послуги, промбезпека, ДСНС) і 9 за типом тканини. Для B2B-пошуку це добре (обидва типи запитів), але потрібна взаємна перелінковка «застосування ↔ тип тканини» `[ПРИПУЩЕННЯ]`.
- **Внутрішня перелінковка** `[ФАКТ]`: головна в HTML посилається на всі 14 категорій (футер) і 4 товари. Категорії в HTML на товари не посилаються, після JS на 9. До більшості карток Google дійде лише через sitemap, і такі сторінки слабо отримують внутрішню вагу `[ПРИПУЩЕННЯ]`. Рекомендація: перелік товарів категорії посиланнями `<a href>` у HTML сервера, пагінація з URL (`?page=2`) замість або разом із кнопкою; блок «Схожі товари» лишити (він є після JS).
- **Хлібні крихти** `[ФАКТ]`: є на категоріях (у HTML) і на картках (лише після JS). Додати розмітку BreadcrumbList.
- **Розмітка (рекомендація, зараз 0 блоків JSON-LD `[ФАКТ]`):**
  - Organization + LocalBusiness на головній і в контактах: назва, логотип, адреса складу, години (Пн–Пт 9–17), телефони, посилання на Google Maps. Розбіжність назви: у title «Різнобит», на логотипі «Разнобитпродукт», у картці Google Maps «Разнобытпродукт ЧАО» `[ФАКТ]`. Яку назву вказувати, вирішує CEO `[НЕВІДОМО]`.
  - Product на картках: name, sku, material, опис, зображення. Розширений сніпет товару в Google зазвичай вимагає ціни (offers) `[ПРИПУЩЕННЯ: перевірити за довідкою Google при складанні ТЗ]`; без ціни розмітка все одно допомагає розуміти сторінку.

## 6. Дані від CEO з Google Search Console й Analytics

Знеособлені експорти в `DATA/inbox/`, період останні 3–6 міс. Якщо щось не налаштовано, просто повідомити про це.

1. **Search Console → «Сторінки» (індексування):** кількість проіндексованих/непроіндексованих і причини (особливо «Проскановано, не проіндексовано», «Виявлено, не проіндексовано», «Дублікат без канонічної»), експорт прикладів URL.
2. **Search Console → «Перевірка URL»** для трьох URL: `/`, `/catalog/workwear/`, `/catalog/workwear/tkan-workwear-tr-35-teflon/` → скриншот «Переглянути проскановану сторінку» (HTML і знімок). Це остаточно підтвердить, що бачить Googlebot.
3. **Search Console → «Ефективність»:** запити й сторінки (кліки, покази, CTR, позиція), експорт CSV.
4. **Search Console → «Файли Sitemap»:** чи подано `sitemap.xml`, статус, кількість виявлених URL.
5. **Search Console → «Досвід сторінок / Core Web Vitals»** (якщо є дані).
6. **Google Analytics:** органічні сесії за посадковими сторінками, події-конверсії (форма, дзвінок, «Замовити зразок»), якщо налаштовані.
7. **PageSpeed Insights** (pagespeed.web.dev, безкоштовно) для тих самих трьох URL, мобільна версія: скриншот або PDF.
8. **Без доступу для ролі:** платформа/CMS сайту і хто може змінювати шаблони рендерингу `[НЕВІДОМО]`.

## Припущення та невідоме
- `[ПРИПУЩЕННЯ]` Google відрендерить JS карток із затримкою, але через порожній title і однаковий сирий HTML значна частина карток не індексується. Підтвердить п. 1–2 розд. 6.
- `[ПРИПУЩЕННЯ]` Редирект без слеша проходить через http. Підтвердить перевірка заголовків відповіді.
- `[НЕВІДОМО]` Кількість сторінок в індексі Google, позиції, трафік, Core Web Vitals, платформа сайту, масштаб дублів товарів по всьому каталогу.

## Висновки та рекомендації
Впевненість: **висока** щодо фактів розд. 1–2 (перевірено на конкретних URL); **середня** щодо впливу на індексацію (без Search Console). Критичний блокер комерційного SEO: картки товарів, тобто основний обсяг сайту, для Google порожні. Поки п. 1–5 розд. 5 не виправлено, нові тексти й семантика (T-03) дадуть менший ефект.
